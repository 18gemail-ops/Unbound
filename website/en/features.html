Features Overview

Eleven pages covering everything from setup to troubleshooting

The sidebar groups pages by scenario: set up your routes under "Proxy & Routing", watch live status under "Monitoring & Data", and handle sudden problems under "Stability & Troubleshooting". Every screenshot in the sections below comes from the real client UI (demo data) and follows the site's light / dark theme.

1. Proxy and routing

"Which line does traffic take" splits into three layers: your subscriptions define the available lines, rules decide the default route, and App Routing decides the exceptions.

Profiles

Import http/https subscription links: click a provider's "Import to Clash / sing-box / Hiddify" button and this app wakes up to finish the import; local YAML config files and single node links can be imported too. Cards can be dragged to reorder, renamed, shared to a phone as a QR code, and refreshed for usage in one click — subscription downloads also detect the provider's site and check its connectivity. Several subscriptions can be enabled at once, with automatic updates on an hourly interval that reload the config and raise a system notification, plus optional auto speed-test and switch to the fastest node after updating. Alerts fire once when traffic hits a threshold, when expiry nears and when it passes; the previous version is archived before each update and can be rolled back at any time.

Proxies

Split view: groups and subscription sources on the left, a grid of node cards on the right. Per-node latency tests, download speed tests (the original node is restored afterwards), test-all, sorting by latency or name, region filters and favorites-only; a top switch hides timed-out nodes, and the card grid adapts to 1–4 columns or auto width — node groups can also be delay-tested automatically on a set interval. With node health monitoring on, each card gains a latency trend line (red dots mark failed tests); with auto-switch-on-failure on, the current node is moved off automatically after repeated failures. Switch between list and map views at any time: the map clusters nodes by region into glowing dots sized by count and colored by latency — click a region to drill down and filter.

App Routing

Bind apps to specific lines by process name or full path, picking directly from processes currently using the network. Selecting two or more lines forms a group automatically, with round-robin or session-persistent policies; the list shows each app's live speed.

Chained proxy

Point a node at an upstream proxy so its traffic relays before egress — handy for restricted nodes. The visual chain editor supports dragging hops to reorder them, picking nodes across groups and placing a proxy group at the head of a chain; saved chains load back into the editor. Node cards carry chain markers with "Entry / Relay / Exit" role badges, and hovering reveals which upstream a node goes through.

Traffic tunnels

Forward a local port to a remote target: the core listens locally on the given port and forwards through a chosen exit (proxy group, node or rule-based routing) to the target host — handy for mapping remote intranet services to your machine. Supports TCP / UDP / mixed protocols.

Quick rules

Right-click any connection on the Connections page and choose "direct for this domain" or "route this domain through a chosen line" — a domain rule is inserted at the very top and takes effect immediately, with no file edits or restarts.

Rules and hit statistics

Four tabs — Rules, Custom rules, Rule sets and Hit statistics — with custom rules added, edited, reordered and saved right on the page, then injected at the top of the runtime config. Hit statistics are sampled every 15 seconds and persisted across restarts, so you can tell whether a rule is actually doing work; a built-in route simulator previews which rule a domain, IP or app will hit (including the group's exit resolution), and works even while the core is stopped.

Method Scope Privileges Best for

Rules and hits

Every rule leaves a trace — no more guessing

See at a glance which rules are doing work and which never fire; before editing, rehearse the outcome in the built-in simulator.

  • Four tabs: rules, custom rules, rule sets and hit statistics, each with its own tab.
  • Visual editing: add, edit, reorder and save custom rules on the page — injected at the top of the runtime config.
  • Traceable hits: hit data is sampled every 15 seconds and persisted across restarts.
  • Route simulation: enter a domain, IP or app and preview locally which rule it hits and which exit it takes.

2. Monitoring and data

The pain with proxies is often "not knowing what's happening right now". That's why every status has somewhere to look.

Dashboard

Core status, version, memory usage and uptime; total up/down traffic and active connections; a live traffic chart. You can also switch each proxy group's current node right on the Dashboard.

Connections

The detail view lists host, process, destination, matched rule, chain and live speed for each connection; the aggregated view groups connection counts by domain. Right-click to create a quick rule for a domain or copy the domain, destination address or process path.

Traffic

Daily up/down usage with 7-day / 30-day / 90-day / all-time ranges, a trend chart and a per-day table; traffic is also accumulated per app process, so you can see who eats the bandwidth. A per-node traffic panel rolls usage up under its exit node (direct traffic counts as DIRECT), showing each line's share at a glance, with one-click reset. Data is persisted — restarts don't clear it.

Logs

Core logs and app logs shown on one screen; app logs carry a [Unbound link] prefix for easy distinction. Filter by Debug / Info / Warning / Error. Logs are also written to logs\app.log with automatic rotation and expiry cleanup.

Desktop floating window

Live speed, current node latency, active connections, today's traffic and proxy status on your desktop. 3 sizes, 3 layouts, 7 color themes, adjustable opacity, mouse pass-through and automatically remembered position.

System tray

The tray icon switches between three states with the proxy status (normal / system proxy / TUN), and each state can be replaced with your own PNG icon. Right-click opens a quick panel to toggle the system proxy or TUN, see speed or open the main window without launching the full app. Click the "node" or "group" row and a standalone node picker pops up beside it: browse by group, click to switch.

Logs

Core and app logs, side by side

When the proxy misbehaves, the logs are the first place to look. App-level actions carry a [Unbound link] prefix and sit alongside core output, so you can tell at a glance who is talking.

  • One screen: core output and app logs interleaved by time on a single page.
  • Level filter: debug / info / warning / error, switchable at any time — see only what matters.
  • Keyword search: search domains, processes or error codes to locate lines fast in long logs.
  • Saved to disk: written to logs\app.log, rotated by size and pruned by age.

3. System integration

Take over what belongs to the system; keep local what belongs to the machine.

System proxy and TUN

Write or restore Windows Internet settings in one click; with "Network environment" automation on, the system proxy and mode can follow the current Wi-Fi name (on at home, off at the office, say). TUN takes over all traffic at the network layer through a virtual adapter, with Mixed / Gvisor / System stacks; when admin rights are needed it guides a UAC-elevated restart. If another program rewrites the system proxy, it is restored automatically. When Store apps can't reach the local proxy because of the system's loopback restriction, the UWP App Tool lifts it in one click.

DNS and LAN

Custom DNS servers (including fallback DNS and static Hosts) can override the subscription's settings, with optional fake-ip acceleration; enabling "allow LAN" lets phones, tablets and other devices on the same subnet use the local proxy directly. The Share to phone button on the same row then shows a QR code — set the phone's Wi-Fi manual proxy as prompted.

Built-in web dashboard

The built-in MetaCubeXD dashboard downloads and hosts itself on first open at http://127.0.0.1:9090/ui/; with LAN enabled, an address for other devices to access the dashboard is also shown.

Global shortcuts

Defaults: Ctrl+Shift+P toggles the system proxy, Ctrl+Shift+T toggles TUN, Ctrl+Shift+U shows the main window, Ctrl+Shift+O toggles the floating window and Ctrl+Shift+M switches the proxy mode. "Update all subscriptions" and "Restart core" can be recorded separately — all shortcuts are customizable or resettable to default.

Global command palette

Press Ctrl+K to bring it up on any page: jump to pages and settings categories, run actions like starting / stopping the core or switching modes, update and toggle subscriptions, check for updates and restore backups, use network rescue, and search and switch nodes — all filterable by keyword and fully keyboard-driven.

Launch at startup and single instance

Optionally run at startup; the app is single-instance, so launching it again brings up the existing window — no two cores fighting over ports. Closing the main window minimizes to the tray instead of exiting. On a fresh install, the first launch opens a four-step guide that walks you through importing a subscription and recommended settings.

Themes and appearance

Dark / light / follow-system modes with instant switching; brand color, secondary color, text color, semantic colors, UI font and custom CSS are all adjustable. The flat design uses black primary buttons and restrained semantic colors — blue for in-progress, green for normal, amber for pending, red for errors.

Interface and language

The UI ships in 13 languages — English, Русский, 中文, فارسی, 한국어, Türkçe, Deutsch, Español, 日本語, 繁體中文 and more — switching instantly. Arabic and Persian flip to right-to-left layouts automatically, numbers and dates follow the chosen locale, and plurals and measure words match local grammar.

Settings

Tabs, groups, cards — three levels of order

Settings is no longer an endless list: six tabs lay things out in groups and cards, so every switch has an obvious home.

  • Appearance and theme: light / dark mode, UI language, accent and semantic colors, UI font and custom CSS all sit under the Appearance tab.
  • Behavior switches: fine-grained toggles like pausing chart rendering when unfocused, Proxies column count and hiding timed-out nodes.
  • Maintenance entries: backup and restore, core and GeoData updates, log cleanup — low-frequency but important actions live under the Maintenance tab.

Configuration capabilities

For those who don't want to touch configs — and those who do

Subscriptions stay pristine while your changes live in a separate file; the two merge only when the runtime config is generated — meaning subscription updates never overwrite your personal settings.

  • Merge override: a few lines of YAML override fields in the subscription (app-level settings such as port and mode are handled by the client), deeply merged recursively.
  • Extension script: built-in QuickJS — one main(config) function batch-renames nodes and adds or removes rules.
  • Node Cleanup: filter nodes by keyword and batch-rename them by rules (with common prefixes/suffixes), rewriting references in proxy groups and rules to match — preview before enabling.
  • App-level settings injection: fields such as port, control secret and mode are written by the client and never overridden by subscription content.
  • Config hot reload: switching nodes, changing ports or DNS applies automatically without interrupting existing connections.
  • Atomic writes: the runtime config is written to a temp file first, then renamed, so the core never reads a half-written file.
  • Config snapshots: before each runtime config is generated the previous version is archived automatically (the latest 10 are kept); if the core won't start, roll back to the last working version in one click — an emergency fallback.

Backup and restore

Export settings, subscriptions, Merge config and the core version into a single JSON file; after switching computers or reinstalling, import it with one click under Settings → Maintenance to restore everything. "Export diagnostics" packages versions, settings, config and recent logs into a ZIP (sensitive fields redacted) to make reporting issues easier.

Cloud backup (WebDAV)

Back up settings, subscriptions, Merge config and extension scripts to your own cloud drive (compatible with Nutstore, Nextcloud, Synology and more), with connection test, status comparison, one-click upload and restore; the password is encrypted by the system and kept on this machine only.

App and core updates

New client versions are checked on startup and can be downloaded and silently installed from within the app, relaunching on the new version; the core and GeoIP / GeoSite GeoData databases also update with one click under Settings → Maintenance, falling back to an accelerated mirror or the local proxy when a direct download fails.

Core watchdog

Automatically restarts the core if it exits unexpectedly, with debounce protection: repeated crashes in a short time won't cause an infinite restart loop — they're faithfully recorded in Logs instead.

4. Stability and troubleshooting

The worst part of proxy trouble is not knowing where the problem is. So diagnosis and repair are split into two steps.

11 network checks

Core status, port listening, system proxy, DNS resolution, DNS takeover, direct exit, proxy exit, WebRTC leaks, current node, direct GitHub access and config loading. Each gives a conclusion, and abnormal items come with suggestions.

Network rescue kit

For five classes of problems — leftover system proxy settings, DNS resolution failures, rewritten DNS servers, abnormal hosts files and damaged network stacks — each is detected with a matching repair button and an automatic re-check afterwards.

Unlock Test

Checks 18 services through the current exit — streaming such as Netflix and Disney+, AI services such as ChatGPT and Claude, and China-side platforms such as Bilibili — and reports one of four states with a note: Unlocked / Partial / Blocked / Failed. Switch the exit node on the page itself to pick a route and retest right away.

A note on privileges

In the one-click rescue, resetting the system proxy and flushing the DNS cache need no admin rights and are always available; only resetting DNS servers, restoring the hosts file and resetting the network stack require UAC elevation, clearly marked in the UI.
