Diagnostics

Diagnostics checks the core, ports, system proxy, DNS, exits and leaks in one pass, with a conclusion and suggestion for each item, plus the network rescue kit.

What this page solves

When pages won't load or the proxy seems ineffective, no need to guess. Entering the page starts the checks automatically; when done, the header summarizes results — e.g., "11 passed", "N notices", "N issues" — so you see the scale of the problem first. The "Re-run checks" button sits top-right and shows "Checking…" while running. Diagnostics only inspects; it never changes system settings — whether and what to repair is up to you.

The 11 automatic checks

There are 11 checks; each gives a conclusion, and abnormal ones show "Suggestion: …" telling you the next step.

CheckWhat it inspects
Core statusWhether the core is running, its version, and whether it's elevated.
Port listeningWhether the mixed and control ports are taken by other programs.
System proxyWhether the system proxy is on and points at the local mixed port.
DNS resolutionResolution time and the DNS addresses in use.
DNS takeoverWhether TUN mode takes over system DNS resolution.
Direct exitThe exit IP probed when connecting directly.
Proxy exitThe exit IP probed through the proxy; if it matches the direct exit, it warns that the exit IP equals the direct one.
WebRTC leaksChecks for public candidate IPs and warns when the real IP could leak.
Current nodeThe current node's latency; when unreachable it suggests picking a working node on the Proxies page.
Direct GitHub accessDirect reachability, timing and HTTP status code.
Config loadingThe number of groups and nodes.

Network rescue kit

The "Network rescue kit" section sits below, described as: "When the proxy exits unexpectedly, DNS breaks or pages won't load: detect first to locate the problem, then repair as prompted." It offers two buttons: "One-click rescue" and "Start check / Re-check".

One-click rescue does two things at once: reset the system proxy and flush the DNS cache. Neither needs admin rights and both take effect immediately — good for the vast majority of temporary network failures. Start check / Re-check runs the dedicated outage checks on their own. Detect first to locate the problem, then decide whether to use one-click rescue.

Outage-specific checks

The dedicated checks cover five classes of problems, each with a matching repair button:

ProblemSymptomRepair button
Leftover system proxyThe proxy still points at 127.0.0.1:7890 while the core isn't running.Reset system proxy
DNS resolution failureDomains can't be resolved.Flush DNS cache (ipconfig /flushdns, no admin needed)
Abnormal DNS serversThe adapter is set to invalid addresses like 0.0.0.0.Reset DNS servers / set to automatic (admin required)
Abnormal hosts fileCustom entries exist, or the file is missing.Restore hosts file (backs up the current content first, then resets to default; admin required)
Direct network unreachableNo internet even without the proxy.Reset network stack (resets winsock and TCP/IP; admin required; takes effect after a reboot)

Privileges and confirmation

Repairs needing admin rights trigger a UAC elevation prompt and only run once approved. Dangerous operations ask for confirmation first, with a red "Run" button — read the prompt before clicking. After a repair, the page re-runs the checks automatically to refresh the conclusions.

Suggested troubleshooting order

Start with the first four checks — core / ports / system proxy / DNS resolution. Once those pass, move on to the exit and leak checks — the scope narrows step by step.
