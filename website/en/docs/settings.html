User Guide

Settings

Ports, mode, TUN, DNS, shortcuts, app logs and backups all live here, split into six tabs: Appearance / System / Network / Tools / Maintenance / About. Each tab is grouped by function, with setting cards under each group title. This page explains every switch's effect and default value.

All settings save instantly

Every switch and input saves immediately; the footer also reads "All settings save instantly" — no OK / Apply buttons. Core-related changes (ports, TUN, DNS) hot-reload or restart the core automatically.

Web dashboard

A built-in MetaCubeXD dashboard, downloaded automatically on first open (about 2.5MB). The local address is http://127.0.0.1:9090/ui/; click "Open dashboard" to enter.

With "Allow LAN connections" on, a LAN dashboard address such as http://192.168.x.x:9090/ui/ also appears here, ready to copy to other devices on the same network with one click.

The control secret protects the External Controller: randomly generated on first run and regenerable with one click; after a change the core restarts automatically, and dashboards or third-party clients using the old secret must switch to the new one.

Network environment

Switches the system proxy and mode automatically according to the connected Wi-Fi name — handy for "on at home, off at the office". The app checks the Wi-Fi name every 10 seconds; when it changes, the first enabled rule that matches is applied from top to bottom. Actions identical to the current state are skipped, so manual adjustments are not overridden. This feature does not change the TUN state.

Tools

Four utilities around rules and connections: lifting the loopback restriction for Store apps, updating the rules database, setting up port-forwarding tunnels, and tidying the node list with keyword filters and replacement rules.

UWP app tool

Apps installed from the Microsoft Store can't reach the local proxy address (127.0.0.1) by default, which shows up as no network inside the app. Click "Manage apps" to open the list and flip the switch for the apps you need — on lifts the loopback restriction, off restores it. Changing loopback exemptions requires admin rights; if it fails, relaunch the app as administrator and retry.

GeoData databases

GEOIP / GEOSITE routing depends on four database files (geoip.dat, geosite.dat, geoip.metadb, GeoLite2-ASN.mmdb); the core loads them from the data directory at startup, and missing or outdated files break the corresponding rules. This section shows each file's size and update time; click "Update databases" to fetch them from the official release page in one go — on direct-connection failure an accelerated mirror is tried automatically, and if that still fails the download goes through the local proxy. Updating all files at once is a large download, so give it a moment.

Traffic tunnels

Forwards a local port to a remote target: the core listens on the given local port and relays through a chosen exit (proxy group or node) to the target host — handy for mapping remote intranet services (databases, remote desktop) to your machine. Each tunnel picks a protocol (TCP / UDP / mixed), a local listen address and port, and a target address and port; with the exit left blank, traffic routes by rules. Tunnels are runtime config; the core restarts automatically after any change.

Node Cleanup

Applies a unified cleanup to the node list when the runtime config is generated — handy when a subscription brings too many noisy nodes. The three parts combine freely: Filter keywords removes any node whose name hits a keyword (case-insensitive); Rename rules replace text in node names in order (case-sensitive; an empty replacement deletes that piece of text); Common prefix / suffix adds a uniform prefix and suffix to every node name after all replacements.

The cleanup also rewrites node references in proxy groups, rules and tunnels, so renamed nodes never break their references. Click "Preview" to see the result before deciding whether to enable it: how many nodes in total, how many filtered, how many renamed — preview works even while the switch is off.

Maintenance

Two groups: "Updates and tests" (subscription, core update, node latency test) and "Data and logs" (config snapshots, backup and restore, app logs).

Subscription

Auto-update interval, in hours, 0 means off, off by default. Once enabled, every subscription in the list updates on schedule in the background; when done, the config reloads automatically and a system notification is sent.

Auto-optimize after update, off by default. Once enabled, every time subscriptions finish updating and the config reloads, the client automatically tests the main proxy group and sets the lowest-latency available node as the current node (applies only to "manual select" proxy groups — auto-test groups make their own pick inside the core); the result is sent as a system notification.

Profile usage alerts is on by default and relies on the traffic and expiry info provided by the subscription source. There are three tiers: Usage alert threshold (alert when used traffic reaches this percentage, default 80%, adjustable from 1 to 100), Expiration alert (alert when remaining days are at or below this value, default 3 days, 0 turns this tier off) and the "expired" alert. Each tier fires only once; after a renewal or plan reset it arms again and alerts again when the condition is met.

Config snapshots

Before each runtime config is generated, the previous config.yaml is archived automatically (the latest 10 are kept). Click View snapshots to see the list; if the core won't start or the config misbehaves, roll back to the last working version in one click. Restoring writes back and hot-reloads the core immediately, archiving the current file first.

Snapshots are an emergency fallback: after restoring, the config is regenerated from your current settings the next time you change something or restart the core.

App logs

The client's own logs are written to logs\app.log in the data directory and rotate by size into archives (app.1.log, app.2.log…); click "Open log folder" to view them. They record the app's own actions (core start/stop, system proxy changes, config and updates), complementing the core's real-time logs on the Logs page — ideal for after-the-fact troubleshooting.

About

The app logo and name sit at the top, with app version, core version and data directory listed below. The data directory is %APPDATA%\com.unboundlink.desktop, copyable with one click — back it up before migrating machines or reinstalling; click "Open folder" to view it in Explorer.

There is an Exit app button — confirming 'Exit Unbound link?' truly ends the program. Check for updates lets you download the installer in the app and complete the upgrade automatically (it installs silently and restarts with the new version); you can cancel and download manually at any time. Help & support opens the website and the online guide. The Developer tools entry opens a built-in debugging panel — not needed for daily use. The bottom of the page reminds you that all settings are saved instantly.

Summary

The three most-used spots: System → the system proxy card; Network → Mode under "Ports and mode"; Maintenance → Data and logs → Export backup. All of them save instantly with no extra confirmation.
