User Guide

Troubleshooting

Common problems below follow Symptom → Cause → Fix, each with concrete steps — just work through them in order.

Pages won't load / no network

Symptom: the browser can't open any page.

Cause: leftover system proxy settings, a bad DNS cache or an unhealthy network stack.

Fix: open Diagnostics and check the first few results; then run "One-click rescue" in the network rescue kit (reset system proxy + flush DNS cache, no admin rights needed). If that still doesn't help, follow the on-screen prompt to reset the network stack — that requires admin rights and takes effect after a reboot.

The proxy isn't taking effect

Symptom: the internet works, but traffic doesn't go through the proxy.

Cause: the mode was switched to Global or Direct; the system proxy is off; the core isn't running.

Fix: open Settings → Network and check the mode is "Rule" (choosing "Global" or "Direct" changes behavior); open Settings → System → System proxy and check it's on; then confirm the core is running via the core status on the Dashboard or in Diagnostics.

Some apps bypass the proxy

Symptom: the browser works, but some programs don't use the proxy — and apps from the Microsoft Store can't open pages at all.

Cause: this is the inherent limitation of system proxies — some programs don't read the setting; Store apps are also subject to the Windows loopback restriction, which blocks access to the local address (127.0.0.1) by default.

Fix: for Store apps, open Settings → Tools → UWP app tool and flip the switch to lift the loopback restriction (needs admin rights); for other programs switch to TUN mode (see Settings → Network → TUN mode), or bind the process to a chosen line with App Routing.

All nodes time out

Symptom: every node tests as timed out.

Cause: the nodes are temporarily unavailable, or the subscription has expired or is stale.

Fix: first click "Test all" on the Proxies page; check whether the subscription has expired and click the "Traffic" button on its card under Profiles to refresh the info; then check the "direct exit / proxy exit" and "current node" conclusions in Diagnostics; you can also click "Update" for the subscription on the Profiles page. To clear useless timed-out nodes, turn on the "Hide timed-out" switch at the top of the Proxies page.

Port already in use

Symptom: the core can't listen; a port conflict is reported.

Cause: the default port is taken by another program.

Fix: the "port listening" check in Diagnostics shows which port is taken; change the mixed proxy port or the control port under Settings → Network → Ports and mode — the core restarts automatically after changes.

Subscription update fails

Symptom: clicking "Update" changes nothing.

Cause: the subscription URL is unreachable, or the current network is down.

Fix: confirm the subscription URL is reachable; check the error lines under Logs; if the network is down, use Diagnostics to locate the problem first.

TUN won't enable / "Not elevated" warning

Symptom: turning on "Enable TUN" has no effect, and the privilege badge shows an orange "Not elevated".

Cause: the current process lacks admin rights, or the install directory is in use.

Fix: go to Settings → Network → TUN mode and click "Restart as administrator", confirm the UAC prompt and retry; also make sure the install directory isn't in use.

Settings changed but nothing happened

Symptom: changing a setting doesn't change the behavior.

Cause: core-related changes need a reload or restart of the core; or config generation failed.

Fix: core-related changes (ports, TUN, DNS) reload or restart the core automatically; if nothing changes, check Logs for config errors and, if needed, check the Merge override or extension script under Profiles — a syntax error makes config generation fail.

Data and backup

Symptom: you need to migrate to a new machine or reinstall Windows.

Cause: the data directory lives under the user folder on the system drive and is lost on reinstall.

Fix: the data directory is %APPDATA%\com.unboundlink.desktop. Before migrating or reinstalling, open Settings → Maintenance → Backup and restore → Export backup, then restore it in the new environment with "Import backup". When you need help troubleshooting, click "Export diagnostics" first and attach the ZIP to your report.

The core won't start

Symptom: the core status never shows Running.

Cause: the install directory is incomplete — the core sidecar is missing or damaged.

Fix: make sure the install directory is complete (the core ships as a sidecar program with the installer); check Logs for errors; go to Settings → Maintenance → Core update and click "Check for updates" to re-fetch the core.

Troubleshooting checklist
  1. Check the core status on the Dashboard.
  2. Check Logs for errors.
  3. Run Diagnostics and check the first 4 items.
  4. Use the network rescue kit.
  5. Check the mode and the system proxy.
  6. Check whether the subscription needs updating.
  7. Check for port conflicts.
  8. If the problem is hard to pin down, click Settings → Maintenance → Backup and restore → Export diagnostics and attach the ZIP to your report.
