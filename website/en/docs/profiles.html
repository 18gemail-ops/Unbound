User Guide

Profiles

Manage your subscription sources here: add links, import local configs, enable one or more subscriptions, import single node links, update node lists, and fine-tune what you get from subscriptions with Merge and Script.

Page overview

Below the title it shows "N subscriptions · M enabled" plus the auto-update status, e.g. "Auto-update every 12 hours" or "Auto-update off". Four buttons sit top-right: "Update all", "Refresh", "Import local config" and "Add subscription". Update all refreshes every subscription in turn; Refresh just re-reads local state; Import local config adds a local YAML file to the list as a subscription.

Adding a subscription

Click "Add subscription" to open the dialog — just two fields:

FieldNotes
Subscription URLRequired; must be an http/https link. Submitting empty shows "Please enter a subscription URL".
NameOptional; the client detects it automatically when left blank.

What each card can do

Each subscription is a card; press and hold to drag-reorder. Cards show the name, a blue "In use" badge on every enabled subscription (several can appear at once), the URL (truncated when long), a relative "Updated …" time, and subscription info (traffic usage, expiry, etc., when the provider supplies it). The right side holds the enable switch followed by the action buttons:

ButtonAction
Enable switchFlip it on to enable this subscription; several can be enabled at once — every enabled subscription carries the blue "In use" badge.
UpdateRe-downloads this subscription's content.
TrafficRefreshes subscription info to check usage and expiry.
QR codeGenerates a QR code to import on your phone.

Multiple subscriptions at once

Several subscriptions can be enabled at once: just flip the enable switch at the top-right of a card, and every enabled subscription carries the blue "In use" badge. The first enabled subscription supplies the base config — port, DNS, run mode — while the others merge their nodes, proxy groups and rules into the same runtime config; the effective order follows the list from top to bottom, so drag cards to reorder.

Version history

Before every remote update, the old content is archived automatically, keeping up to 5 versions. Click the clock icon on a subscription card to open the version history dialog, which shows each snapshot's time and node count; click Restore to roll back to that version.

If the subscription is enabled, rolling back hot-reloads the running config immediately; the current content is archived first, so you can always undo the rollback. Local configs don't take part in remote updates, so they have no version history. After an update the card shows change badges for node and rule counts (green for growth, red for shrink), and a warning pops up if the node count drops by more than half.

Importing a local config

Click "Import local config" and pick a local YAML file; the client copies it into the data directory and adds it to the list as a subscription, tagged "Local" and labeled "local config file (excluded from remote updates)". Handy for configs you maintain yourself or got from elsewhere — no need to upload to a server first.

Local subscriptions take part in neither remote updates nor auto-update; "Update all" skips them. The file lives in the data directory — re-import it when moving to a new version. Success shows "Local config imported".

Manual Nodes

The "Manual Nodes" card at the bottom of the page holds single nodes outside any subscription: click "Import links", paste the node links into the dialog (one per line), click "Parse" to preview, then "Import N" to finish. Common protocols are supported — ss / vmess / vless / trojan / hysteria2 / tuic / socks5 / http; failed lines are reported individually and duplicate names are skipped automatically.

Manual nodes live in the data directory and merge into a proxy group of the same name when the runtime config is generated (default group name: "Manual Nodes"). Remove imported nodes one by one on the card; changes save immediately and hot-reload the config.

Global override config (Merge)

At the bottom sits the "Global override config" card with a Merge tag. Open it and write a YAML snippet — when the runtime config is generated it's deeply merged recursively with the subscription to override its fields (app-level settings such as port, control secret and mode are written by the client — writing them here has no effect; change them under Settings → Network). Saving shows "Merge config saved and applied".

Global extension script (Script)

Next to it, the "Global extension script" card with a Script tag. Open it and write JavaScript implementing function main(config){ … return config }. The client runs it on the built-in QuickJS engine to batch-rename nodes, add or remove rules and more. Saving shows "Extension script saved and applied". A sample script using regex to strip ads from node names comes built in.

Auto-update

The auto-update interval is set under Settings → Maintenance → Subscription, in hours, 0 means off (off by default). Once enabled, every subscription in the list updates on schedule in the background; when done, the config reloads automatically and a system notification is sent.

Two subscription-linked switches live in the same place: "Auto-optimize after update" is off by default — once enabled, every time a subscription update finishes and the config reloads, it tests the main proxy group and switches the current node to the lowest-latency one; "Profile usage alerts" is on by default and sends a system notification when used traffic reaches the threshold, remaining days run low or the subscription has expired, each tier firing only once. Both rely on the traffic and expiry info provided by the subscription source.

If updates fail, check the network first

Failed updates usually mean a dead URL or a broken connection. Check the network in Diagnostics, then come back and retry "Update".
