User Guide

Proxies

This page browses the nodes and groups your subscriptions bring, switches lines, tests latency, favorites nodes and configures chained proxies for restricted nodes.

Page layout

A column on the left lists entries: groups, node sources (providers / subscriptions) and other groups. Click an entry to show its nodes on the right. Each entry has a ⟳ icon that "updates the node list from the source right now", re-fetching the nodes under that entry. Group entries carry notes like: other groups pick routes by their own policy, e.g. auto-selecting the lowest-latency node. Their routes come from the subscription — no need to specify them one by one.

Search and sorting

The toolbar at the top-right narrows the range and changes display order. The search box covers groups, nodes and providers, and accepts region abbreviations like hk. The sort dropdown offers default order, sort by latency and sort by name. The difference: search filters — only matches remain; sorting just reorders without removing anything.

Filter bar

Below the toolbar sits the filter bar with region pills (including "All") and "Favorites only". Region pills show nodes from one region; Favorites only shows starred nodes. Drag the bar sideways to pan through it — no need to squeeze many regions onto one screen.

Map view

A "List / Map" toggle sits at the top-right of the node list. Switch to map view and a world map appears on the right, with nodes aggregated into dots by country and region: the region a dot lands in is where your nodes are, so the global spread reads at a glance.

Dot size reflects how many nodes a region has — bigger means more. Color reflects the best latency within the region: green is fast, orange is moderate, red is slow, and grey means no node there has been latency-tested yet. The region of the node currently in use is ringed with a highlight to locate the active line at a glance. Hover a dot to see the region name, node count and best latency.

Click any dot to filter nodes by that region: the view switches back to the list, the matching region pill in the filter bar becomes selected, and only that region's nodes remain on the right — "see the map, drill into the list" in one step. Click "All" in the filter bar to restore everything. The list and the map share the same nodes and filters, so switching back and forth loses nothing.

Map data is built into the app; rendering needs no network and no online map service.

Node cards

Each node card shows the node name and latency (color-coded so speed reads at a glance). Clickable elements on the card:

ElementAction
StarFavorites the node; favorites always float to the top.
Lightning buttonTests this node's latency.
Gauge buttonDownload speed test, about 10 seconds.
Chain badgeNodes in a chain show role tags after their names: Entry (first hop) / Relay / Exit (final landing); hover to see the order.
Latency trendWith Node health monitoring on, each card carries a recent latency line (red dots mark failed tests), so you can tell at a glance whether a node is stable.

The two kinds of speed tests

The lightning button runs a latency test — the same figure shown on the card, good for quickly comparing who's closer. The gauge button runs a download speed test, taking about 10 seconds; during the test the exit switches to that node temporarily and restores the previous node afterwards, so there's nothing to switch back manually. To triage a large batch of nodes, "Test all" in the toolbar is easier.

About test results

Test results stay valid for about 10 minutes, then clear automatically so stale data doesn't mislead. A node with no latency number usually just has expired results — test again. To keep timed-out nodes out of the list, turn on "Hide timed-out" at the top of the page.

With Node health monitoring enabled (Settings → Network), every test result is recorded on a rolling basis and drawn as a latency trend line on the node card: the line reflects recent latency levels and red dots mark failed tests; if the node in use keeps failing tests, the app sends a system notification and, with Automatic failover on, also switches the line to the fallback node (or the lowest-latency available node in the group) and reports the result. Right after you enable monitoring there's little data, so the line fills in as you test more or as scheduled tests run.

Chained proxy

Some nodes are restricted or unstable when reached directly; give them a front relay so traffic goes through the relay first and exits here — one such relationship is a "chain". Click "Chained proxy rules" in the toolbar to open the chain editor (a drawer on the right): saved chains on the left, a visual builder on the right, with a complete chain shown as "This device → Hop 1 → Hop 2 → Internet".

To build a chain: click "New chain" and click hops in the candidate list below to add them in order. The list supports search and region filters, pins favorites on top, shows each node's latest latency on the right (from the core's test records; untested nodes show none), and pools all direct nodes — no need to switch left-side groups when picking across them. Click a hop again to remove it; drag hop blocks to reorder; click the + between hops to set the insertion point, and the next hop you click goes there.

ElementNotes
Proxy groupCan only be the chain's first hop (entry), e.g. "HK Auto → landing node"; regular nodes can go anywhere.
DragPress and drag a hop block to reposition it in the chain.
× buttonRemoves the hop; the + between hops sets where the next hop is inserted.
Invalid markerHops no longer present in the enabled subscriptions are flagged in red; "Remove invalid chains" cleans them up in one click, applied on save.

Clicking "Save and apply" writes the whole chain and hot-reloads the runtime config at once — effective immediately. To use it, select the chain's last node and the full path is used; selecting a middle hop passes only through the hops before it. The first hop alone isn't a chain (it's a relay referenced by later hops). Chained latency is roughly the sum of all hops — usually slower, but potentially more stable.

To quickly give one node a front proxy, still click the chain button on its card and pick a front node or group in the dialog; such quick rules also appear in the chain editor as chains and remain editable.

Switching nodes applies instantly

Switching nodes on the Dashboard or this page hot-reloads the config — no core restart, no stop-and-start needed.
