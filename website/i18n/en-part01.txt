19|Subscription management and auto-update
20|Import a subscription with a single link and see usage and expiry right on the card. Set auto-update every 1–24 hours; when an update finishes, the config reloads automatically and a system notification is sent.
21|Per-process routing

23|Chained proxy
24|Assign a front proxy to a restricted node so traffic goes through the relay first. Set it with the chain button on the node card; latency is simply the sum of both hops.
25|Merge override + extension script

29|Network rescue kit
30|When the proxy exits unexpectedly and your browser can't open pages, Diagnostics pinpoints the problem first, then one click resets the system proxy and flushes the DNS cache, with an automatic re-check.

40|About configuration
41|Subscriptions, overrides, scripts — three layers, each minding its own business
42|Subscriptions stay pristine and follow upstream updates while your personal changes live in separate files — no overwriting. Swap subscriptions or providers without reconfiguring everything.
43|<b>Profiles</b>: http/https subscription links, drag to reorder, rename, generate a QR code to share with your phone, and view live usage.
44|<b>Merge override</b>: a few lines override fields in the subscription (except app-level settings such as port and mode), deeply merged recursively when the runtime config is generated.
45|<b>Extension script</b>: built-in QuickJS engine — one <code>main(config)</code> function batch-renames nodes and adds or removes rules.
46|<b>Runtime config</b>: app-level fields such as port, secret and mode are injected by the client and never overridden by subscriptions; config changes hot-reload automatically — no manual core restart.

48|App Routing
49|Let every app take its own route
50|No need to switch everything to global for one game. Bind lines by process name or full path; all other traffic keeps following the rules.
51|<b>Easy to pick</b>: choose straight from processes currently using the network, with app icons — no need to remember exe names.
52|<b>Flexible binding</b>: one line goes directly to that group; two or more lines form a load-balance group so multiple lines serve the same app together.
53|<b>Load-balance policies</b>: round-robin spreads connections across lines; session-persistent keeps a session on one line.
54|<b>Visible results</b>: the binding list shows the app's live up/down speed — one glance tells whether it's working.

57|First it tells you what's wrong, then it helps you fix it

104|Features Overview
105|Eleven pages covering everything from setup to troubleshooting
106|The sidebar groups pages by scenario: set up your routes under "Proxy & Routing", watch live status under "Monitoring & Data", and handle sudden problems under "Stability & Troubleshooting". Every screenshot in the sections below comes from the real client UI (demo data) and follows the site's light / dark theme.
107|1. Proxy and routing
108|"Which line does traffic take" splits into three layers: your subscriptions define the available lines, rules decide the default route, and App Routing decides the exceptions.
109|Profiles
110|Import http/https subscription links: click a provider's "Import to Clash / sing-box / Hiddify" button and this app wakes up to finish the import; local YAML config files and single node links can be imported too. Cards can be dragged to reorder, renamed, shared to a phone as a QR code, and refreshed for usage in one click — subscription downloads also detect the provider's site and check its connectivity. Several subscriptions can be enabled at once, with automatic updates on an hourly interval that reload the config and raise a system notification, plus optional auto speed-test and switch to the fastest node after updating. Alerts fire once when traffic hits a threshold, when expiry nears and when it passes; the previous version is archived before each update and can be rolled back at any time.
111|Proxies
112|Split view: groups and subscription sources on the left, a grid of node cards on the right. Per-node latency tests, download speed tests (the original node is restored afterwards), test-all, sorting by latency or name, region filters and favorites-only; a top switch hides timed-out nodes, and the card grid adapts to 1–4 columns or auto width — node groups can also be delay-tested automatically on a set interval. With node health monitoring on, each card gains a latency trend line (red dots mark failed tests); with auto-switch-on-failure on, the current node is moved off automatically after repeated failures. Switch between list and map views at any time: the map clusters nodes by region into glowing dots sized by count and colored by latency — click a region to drill down and filter.
113|App Routing
114|Bind apps to specific lines by process name or full path, picking directly from processes currently using the network. Selecting two or more lines forms a group automatically, with round-robin or session-persistent policies; the list shows each app's live speed.
115|Chained proxy
116|Point a node at an upstream proxy so its traffic relays before egress — handy for restricted nodes. The visual chain editor supports dragging hops to reorder them, picking nodes across groups and placing a proxy group at the head of a chain; saved chains load back into the editor. Node cards carry chain markers with "Entry / Relay / Exit" role badges, and hovering reveals which upstream a node goes through.
117|Traffic tunnels
118|Forward a local port to a remote target: the core listens locally on the given port and forwards through a chosen exit (proxy group, node or rule-based routing) to the target host — handy for mapping remote intranet services to your machine. Supports TCP / UDP / mixed protocols.
119|Quick rules
120|Right-click any connection on the Connections page and choose "direct for this domain" or "route this domain through a chosen line" — a domain rule is inserted at the very top and takes effect immediately, with no file edits or restarts.
121|Rules and hit statistics
122|Four tabs — Rules, Custom rules, Rule sets and Hit statistics — with custom rules added, edited, reordered and saved right on the page, then injected at the top of the runtime config. Hit statistics are sampled every 15 seconds and persisted across restarts, so you can tell whether a rule is actually doing work; a built-in route simulator previews which rule a domain, IP or app will hit (including the group's exit resolution), and works even while the core is stopped.

145|<b>Traceable hits</b>: hit data is sampled every 15 seconds and persisted across restarts.

148|2. Monitoring and data
149|The pain with proxies is often "not knowing what's happening right now". That's why every status has somewhere to look.
150|Dashboard
151|Core status, version, memory usage and uptime; total up/down traffic and active connections; a live traffic chart. You can also switch each proxy group's current node right on the Dashboard.
152|Connections
153|The detail view lists host, process, destination, matched rule, chain and live speed for each connection; the aggregated view groups connection counts by domain. Right-click to create a quick rule for a domain or copy the domain, destination address or process path.
154|Traffic
155|Daily up/down usage with 7-day / 30-day / 90-day / all-time ranges, a trend chart and a per-day table; traffic is also accumulated per app process, so you can see who eats the bandwidth. A per-node traffic panel rolls usage up under its exit node (direct traffic counts as DIRECT), showing each line's share at a glance, with one-click reset. Data is persisted — restarts don't clear it.
156|Logs
157|Core logs and app logs shown on one screen; app logs carry a <code>[Unbound link]</code> prefix for easy distinction. Filter by Debug / Info / Warning / Error. Logs are also written to <code>logs\app.log</code> with automatic rotation and expiry cleanup.
158|Desktop floating window
159|Live speed, current node latency, active connections, today's traffic and proxy status on your desktop. 3 sizes, 3 layouts, 7 color themes, adjustable opacity, mouse pass-through and automatically remembered position.
160|System tray
161|The tray icon switches between three states with the proxy status (normal / system proxy / TUN), and each state can be replaced with your own PNG icon. Right-click opens a quick panel to toggle the system proxy or TUN, see speed or open the main window without launching the full app. Click the "node" or "group" row and a standalone node picker pops up beside it: browse by group, click to switch.
162|Logs
163|Core and app logs, side by side
164|When the proxy misbehaves, the logs are the first place to look. App-level actions carry a [Unbound link] prefix and sit alongside core output, so you can tell at a glance who is talking.
165|<b>One screen</b>: core output and app logs interleaved by time on a single page.
166|<b>Level filter</b>: debug / info / warning / error, switchable at any time — see only what matters.
167|<b>Keyword search</b>: search domains, processes or error codes to locate lines fast in long logs.
168|<b>Saved to disk</b>: written to <code>logs\app.log</code>, rotated by size and pruned by age.
169|<a class="btn btn-ghost" href="./docs/logs.html">Read the Logs guide →</a>
170|System tray
171|Half the job done without opening the main window
172|Right-click the tray icon for a quick panel: system proxy, mode, nodes and live speed all on one screen. Click the "Node" or "Group" row and a separate picker pops up beside it — click to switch.
173|<b>One-screen control</b>: proxy switch, mode, nodes and groups, profiles, theme and the floating widget switch all live in the panel.
174|<b>Node picker</b>: groups on the left, nodes with latency on the right, the current one ticked.
175|<b>Three-state icon</b>: normal / system proxy / TUN each get their own icon — all three replaceable with your own PNG.

177|3. System integration
178|Take over what belongs to the system; keep local what belongs to the machine.
179|System proxy and TUN
180|Write or restore Windows Internet settings in one click; with "Network environment" automation on, the system proxy and mode can follow the current Wi-Fi name (on at home, off at the office, say). TUN takes over all traffic at the network layer through a virtual adapter, with Mixed / Gvisor / System stacks; when admin rights are needed it guides a UAC-elevated restart. If another program rewrites the system proxy, it is restored automatically. When Store apps can't reach the local proxy because of the system's loopback restriction, the UWP App Tool lifts it in one click.
181|DNS and LAN
182|Custom DNS servers (including fallback DNS and static Hosts) can override the subscription's settings, with optional fake-ip acceleration; enabling "allow LAN" lets phones, tablets and other devices on the same subnet use the local proxy directly. The Share to phone button on the same row then shows a QR code — set the phone's Wi-Fi manual proxy as prompted.
183|Built-in web dashboard
184|The built-in MetaCubeXD dashboard downloads and hosts itself on first open at <code>http://127.0.0.1:9090/ui/</code>; with LAN enabled, an address for other devices to access the dashboard is also shown.
185|Global shortcuts
186|Defaults: <code>Ctrl+Shift+P</code> toggles the system proxy, <code>Ctrl+Shift+T</code> toggles TUN, <code>Ctrl+Shift+U</code> shows the main window, <code>Ctrl+Shift+O</code> toggles the floating window and <code>Ctrl+Shift+M</code> switches the proxy mode. "Update all subscriptions" and "Restart core" can be recorded separately — all shortcuts are customizable or resettable to default.
187|Global command palette
188|Press <code>Ctrl+K</code> to bring it up on any page: jump to pages and settings categories, run actions like starting / stopping the core or switching modes, update and toggle subscriptions, check for updates and restore backups, use network rescue, and search and switch nodes — all filterable by keyword and fully keyboard-driven.
189|Launch at startup and single instance
190|Optionally run at startup; the app is single-instance, so launching it again brings up the existing window — no two cores fighting over ports. Closing the main window minimizes to the tray instead of exiting. On a fresh install, the first launch opens a four-step guide that walks you through importing a subscription and recommended settings.
191|Themes and appearance
192|Dark / light / follow-system modes with instant switching; brand color, secondary color, text color, semantic colors, UI font and custom CSS are all adjustable. The flat design uses black primary buttons and restrained semantic colors — blue for in-progress, green for normal, amber for pending, red for errors.
193|Interface and language
194|The UI ships in 13 languages — English, Русский, 中文, فارسی, 한국어, Türkçe, Deutsch, Español, 日本語, 繁體中文 and more — switching instantly. Arabic and Persian flip to right-to-left layouts automatically, numbers and dates follow the chosen locale, and plurals and measure words match local grammar.
195|Settings
196|Tabs, groups, cards — three levels of order
197|Settings is no longer an endless list: six tabs lay things out in groups and cards, so every switch has an obvious home.
198|<b>Appearance and theme</b>: light / dark mode, UI language, accent and semantic colors, UI font and custom CSS all sit under the Appearance tab.
199|<b>Behavior switches</b>: fine-grained toggles like pausing chart rendering when unfocused, Proxies column count and hiding timed-out nodes.
200|<b>Maintenance entries</b>: backup and restore, core and GeoData updates, log cleanup — low-frequency but important actions live under the Maintenance tab.
201|<a class="btn btn-ghost" href="./docs/settings.html">Read the Settings guide →</a>
202|Configuration capabilities
203|For those who don't want to touch configs — and those who do
204|Subscriptions stay pristine while your changes live in a separate file; the two merge only when the runtime config is generated — meaning subscription updates never overwrite your personal settings.
205|<b>Merge override</b>: a few lines of YAML override fields in the subscription (app-level settings such as port and mode are handled by the client), deeply merged recursively.
206|<b>Extension script</b>: built-in QuickJS — one <code>main(config)</code> function batch-renames nodes and adds or removes rules.
207|<b>Node Cleanup</b>: filter nodes by keyword and batch-rename them by rules (with common prefixes/suffixes), rewriting references in proxy groups and rules to match — preview before enabling.
208|<b>App-level settings injection</b>: fields such as port, control secret and mode are written by the client and never overridden by subscription content.
209|<b>Config hot reload</b>: switching nodes, changing ports or DNS applies automatically without interrupting existing connections.
210|<b>Atomic writes</b>: the runtime config is written to a temp file first, then renamed, so the core never reads a half-written file.
211|<b>Config snapshots</b>: before each runtime config is generated the previous version is archived automatically (the latest 10 are kept); if the core won't start, roll back to the last working version in one click — an emergency fallback.
212|Backup and restore
213|Export settings, subscriptions, Merge config and the core version into a single JSON file; after switching computers or reinstalling, import it with one click under Settings → Maintenance to restore everything. "Export diagnostics" packages versions, settings, config and recent logs into a ZIP (sensitive fields redacted) to make reporting issues easier.
214|Cloud backup (WebDAV)
215|Back up settings, subscriptions, Merge config and extension scripts to your own cloud drive (compatible with Nutstore, Nextcloud, Synology and more), with connection test, status comparison, one-click upload and restore; the password is encrypted by the system and kept on this machine only.
216|App and core updates
217|New client versions are checked on startup and can be downloaded and silently installed from within the app, relaunching on the new version; the core and GeoIP / GeoSite GeoData databases also update with one click under Settings → Maintenance, falling back to an accelerated mirror or the local proxy when a direct download fails.
218|Core watchdog
219|Automatically restarts the core if it exits unexpectedly, with debounce protection: repeated crashes in a short time won't cause an infinite restart loop — they're faithfully recorded in Logs instead.
220|4. Stability and troubleshooting
221|The worst part of proxy trouble is not knowing where the problem is. So diagnosis and repair are split into two steps.
222|11 network checks
223|Core status, port listening, system proxy, DNS resolution, DNS takeover, direct exit, proxy exit, WebRTC leaks, current node, direct GitHub access and config loading. Each gives a conclusion, and abnormal items come with suggestions.
224|Network rescue kit
225|For five classes of problems — leftover system proxy settings, DNS resolution failures, rewritten DNS servers, abnormal hosts files and damaged network stacks — each is detected with a matching repair button and an automatic re-check afterwards.
226|Unlock Test
227|Checks 18 services through the current exit — streaming such as Netflix and Disney+, AI services such as ChatGPT and Claude, and China-side platforms such as Bilibili — and reports one of four states with a note: Unlocked / Partial / Blocked / Failed. Switch the exit node on the page itself to pick a route and retest right away.
228|A note on privileges
229|In the one-click rescue, resetting the system proxy and flushing the DNS cache need no admin rights and are always available; only resetting DNS servers, restoring the hosts file and resetting the network stack require UAC elevation, clearly marked in the UI.

357|FAQ
358|Start here — chances are you'll find your answer
359|Installation failures, connection issues, "where is that switch" — the guide covers them all; this page gathers the most frequently asked questions.
360|About the software itself
361|How does Unbound link relate to Clash-based clients?
362|Unbound link is a Windows desktop client whose networking power comes entirely from the <b>mihomo core</b> (the successor of the Clash Meta line) — it implements no proxy protocols itself. Its job is subscription management, runtime config generation, core lifecycle and supervision, and observing and controlling the core through its API.
363|Do I need to download and place the core myself?
364|No. The core (mihomo) and TUN driver ship with the installer, and the client starts and stops them. You don't edit config files by hand either — the runtime config is generated by the client from your subscription and settings.
365|The core itself can be checked and updated under Settings → Maintenance → Core update.
366|Is macOS or Linux supported?
367|Currently only 64-bit Windows 10 / 11. Some features (system proxy writes, the TUN virtual adapter, the tray and UAC elevation) rely on Windows capabilities.
368|Where do I get a subscription?
369|Subscriptions come from your own provider — the client bundles none and resells none. Once you have a link like <code>https://…</code>, paste it into Profiles → Add subscription.
370|Can I import multiple subscriptions?
371|You can import and keep multiple subscriptions, and drag cards to reorder them. Each subscription has its own enable switch — several can be on at once: the first enabled subscription supplies the base config (port / DNS / mode), while the others merge in their nodes, proxy groups and rules; the effective order follows the list from top to bottom. Changing what's enabled regenerates the runtime config.
372|Making the proxy work
373|The system proxy is on — why do some apps still bypass it?
374|That's the inherent limitation of system proxies: only programs that read Windows Internet settings (browsers, most desktop software) use it. Games, some command-line tools and apps with their own network stack ignore this setting.
375|Two fixes: enable <b>TUN mode</b> (the virtual adapter takes over all traffic at the network layer; admin rights required), or bind the process to a chosen line with <b>App Routing</b>.
376|Apps from the Microsoft Store can't reach the network — what should I do?
377|Windows blocks Store apps from accessing local addresses (<code>127.0.0.1</code>) by default, so they can't use the local proxy directly — the app shows no connectivity, spinning forever.
378|Go to Settings → Tools → UWP App Tool → Manage apps and flip the switch to lift the loopback restriction; this needs admin rights — if it fails, restart the app as administrator and try again.
379|System proxy, TUN mode or App Routing — which should I use?
380|<b>System proxy</b>: covers browsers and most software, needs no extra privileges — the everyday first choice.
381|<b>TUN mode</b>: covers all traffic, including apps that ignore the system proxy; requires admin rights.
382|<b>App Routing</b>: affects only bound processes — for singling out individual apps onto dedicated lines.
383|All three can be enabled at the same time without conflict.
384|What's the difference between Rule, Global and Direct modes?
385|<b>Rule</b> decides each connection's path from the subscription and your own rules — the everyday mode; <b>Global</b> ignores rules and sends everything through the selected exit; <b>Direct</b> bypasses the proxy entirely.
386|Switch under Settings → Network → Mode. Note: in Global or Direct mode, rules in the rule list no longer take effect.
387|Quick rules vs. subscription rules — which wins?
388|Quick rules. Domain rules you create by right-clicking on the Connections page are inserted at the very top of the rule list, so they match before subscription rules and take effect immediately — no core restart needed.
389|All nodes show as timed out — what now?
390|Check in order: ① On the Proxies page click "Test all" for the latest latencies; ② On the Profiles page click "Traffic" on the card to refresh usage info and confirm the subscription hasn't expired; ③ Click "Update" to re-fetch the subscription; ④ Check the "direct exit / proxy exit" and "current node" conclusions in Diagnostics.
391|For more scenarios see <a href="./docs/troubleshooting.html">Troubleshooting</a>.
392|Does switching nodes drop existing connections?
393|Switching nodes or changing DNS/ports applies to the core via hot reload — the core process itself is not restarted. Connections already in flight may be re-established because the exit changed; that's normal proxy behavior.
394|Privileges and data
395|Why do some operations require admin rights?
396|Operations that modify system-level settings require admin rights: enabling TUN mode, resetting DNS servers, restoring the hosts file and resetting the network stack. The client marks them clearly in the UI and elevates via UAC when executed — never silently.
397|Resetting the system proxy and flushing the DNS cache in one-click rescue need no admin rights and are always available.
398|Does the software collect or upload my data?
399|No account required, no telemetry. Settings, subscriptions, statistics and logs all live in the local data directory <code>%APPDATA%\com.unboundlink.desktop</code>.
400|The app makes only three kinds of outbound requests: fetching your subscription links, checking for and downloading core updates, and probe requests during Diagnostics and speed tests (e.g., 204 check endpoints and your own nodes).
401|Switching computers or reinstalling — how do I keep my setup?
402|Settings → Maintenance → Backup and restore → Export backup produces a JSON file with your settings, subscriptions, Merge config and core version. Install in the new environment and click "Import backup" to restore (this overwrites current settings and subscriptions).
403|I want to report a problem — what information helps most?
404|Settings → Maintenance → Backup and restore → Export diagnostics produces a ZIP with app and core versions, current settings, runtime config and recent logs — secrets and other sensitive fields are redacted automatically, so you can attach it directly to your report.
405|After uninstalling, my browser can't open pages?
406|That means the system proxy was still on at uninstall time and the browser is still pointing at the local proxy port. Fix: reinstall and click "One-click rescue" in Diagnostics → Network rescue (reset system proxy + flush DNS cache), or clear the proxy server in Windows Internet Options → Connections → LAN settings.
407|In the future, turn off the system proxy under Settings → System → System proxy before uninstalling.
408|Will uninstalling delete my settings and subscriptions?
409|No. The uninstaller only removes program files; the data directory stays. To clean up completely, delete <code>%APPDATA%\com.unboundlink.desktop</code> manually.
410|Usage details
411|Which ports are used by default? What if they're taken?
412|The default mixed proxy port is <code>7890</code> and the control API port is <code>9090</code>. The "port listening" check in Diagnostics tells you whether the ports are properly listened on or taken by another program. Change them under Settings → Network → Ports and mode; the core restarts automatically after changes.
413|Why does the download speed test run only about 10 seconds — and switch nodes temporarily?
414|The gauge icon on a node card runs a download speed test; reflecting real bandwidth takes actual downloading, hence roughly 10 seconds. The test temporarily switches the exit to that node and restores the previously selected node when done. Results are cleared automatically after about 10 minutes so stale data doesn't mislead.
415|Why do the logs have two sources?
416|Logs from the core itself (connections, rule matching, etc.) come over the core's live channel; the client's own operation logs (subscription updates, config reloads, core start/stop, etc.) carry a <code>[Unbound link]</code> prefix. Both appear together in time order on the Logs page, and level filters apply to both.
417|Where does the app go when I close the window?
418|By default "minimize to tray on close" is on — the close button only hides the window and the proxy keeps running. Right-click the tray icon to reopen the main window or exit completely. This behavior can be changed under Settings → System → Tray and watchdog.
419|How do I customize the floating window — and will it block mouse clicks?
420|The floating window offers 3 sizes, 3 layouts (card / capsule / gauge) and 7 color themes; latency, connection count, traffic chart, today's traffic and proxy status can each be toggled, and opacity adjusted. If clicks bother you, enable "mouse pass-through" under Settings → System → Tray and watchdog.
421|Are there keyboard shortcuts?
422|Five global shortcuts by default: <code>Ctrl+Shift+P</code> toggles the system proxy, <code>Ctrl+Shift+T</code> toggles TUN mode, <code>Ctrl+Shift+U</code> shows the main window, <code>Ctrl+Shift+O</code> toggles the traffic floating window and <code>Ctrl+Shift+M</code> cycles the proxy mode (Rule → Global → Direct). "Update all subscriptions" and "Restart core" are unbound by default and can be recorded. Find them under Settings → System → Global shortcuts; record your own or reset to defaults.
423|Still stuck?
424|Check the <a href="./docs/troubleshooting.html">Troubleshooting</a> and <a href="./docs/diagnose.html">Diagnostics</a> chapters of the guide first; if that doesn't help, open an issue in the repository — including error lines from the Logs page and the Diagnostics conclusions speeds up the investigation.

426|The full guide walks through every screen, including each switch's location and default value.

1062|Switch the level to Debug first, then reproduce the problem, so the full sequence around the failure gets recorded; once found, set it back to Info to keep logs from bloating.

1064|With lots of logs, reading in this order is most efficient:
1065|First find error lines with the <code>[Unbound link]</code> prefix — they point straight at the client step that failed.
1066|Then the core's error lines — the concrete failures at the address, rule or connection level.
1067|Finally warning lines — to check for overlooked risks.

1538|Node Cleanup

1603|Traffic
1604|The Traffic page records this machine's daily up and down traffic through the core, so you can review usage trends over time.
1605|Traffic: totals for download / upload, overall traffic, daily average and the peak day up top; a download / upload bar chart in the middle; per-day and per-app tables below.
1606|What this page solves
1607|It answers "how much traffic did I use these days". All data comes from the local core — no server collects it; what you see is this computer's actual usage.
1608|Choosing a time range
1609|The top of the page switches between four time ranges:
1610|<b>Last 7 days</b> — usage over the past week.
1611|<b>Last 30 days</b> — usage over the past month.
1612|<b>Last 90 days</b> — usage over the past three months.
1613|<b>All</b> — every record in history.
1614|After switching, the chart and table below update in sync. Shorter ranges show clearer trends; longer ranges are better for overall scale. "Last 7 days" is enough for daily checks — reach for "Last 30 days" or "Last 90 days" to see long-term usage. Switching only affects the display; no historical data is deleted.
1615|What to look at and how
1616|The page presents data two ways at once — a trend chart and a detail table: the chart shows the curve's ups and downs so you can spot high-traffic days at a glance; the table gives each day's exact numbers. The table has four columns:
1617|Column
1618|Meaning
1619|<b>Date</b>
1620|The day this row covers.
1621|<b>Download</b>
1622|Total traffic received that day.
1623|<b>Upload</b>
1624|Total traffic sent that day.
1625|<b>Total</b>
1626|Combined up and down traffic for the day.
1627|If the current range has no records yet, the page shows "No records in this range". Widen the range, or come back after using the app for a while.
1628|Traffic by app
1629|At the bottom of the page there is an <b>App traffic</b> panel that groups traffic by originating process, showing which app used the most bandwidth over the period. The table has five columns — app, download, upload, total and last active — sorted by total, highest first.
1630|Data is sampled from connection records every 15 seconds while the core runs; only connections with an identifiable process are counted. The list may be empty right after start-up and fills in shortly. Totals persist across restarts. To start over, click Reset at the panel's top-right to clear all per-app totals; daily records are not affected.
1631|Traffic by node
1632|Below the <b>App traffic</b> panel there is a <b>Node traffic</b> panel that groups traffic by the exit node each connection finally leaves through, with direct traffic listed separately as a <b>DIRECT</b> row — handy for comparing how much went through the proxy and how much went direct. The table has five columns — node, download, upload, total and last active — sorted by total, highest first.
1633|Data is likewise sampled every 15 seconds while the core runs and accumulated; totals persist across restarts. To start over, click Reset at the panel's top-right to clear all per-node totals; daily records and App traffic are not affected.
1634|Where the data is stored
1635|Data is recorded continuously while the client runs and stored in the data directory: daily records in <code>traffic_history.json</code>, per-app traffic in <code>app_traffic.json</code> and per-node traffic in <code>node_traffic.json</code>. Therefore <b>history is kept after a restart</b> and is not lost when you exit. All these files are maintained automatically by the client — no manual editing needed.
1636|Only traffic through the core is counted
1637|Only traffic that goes through the core is counted. Direct connections that bypass the core aren't included, so the totals may be lower than the adapter's actual usage.
1638|About clearing records
1639|Daily records have no dedicated clear button — you can overwrite them indirectly by importing a backup under Settings → Maintenance → Backup & restore. Per-app and per-node totals can be cleared with Reset at each panel's top-right.

1654|Troubleshooting
1655|Common problems below follow Symptom → Cause → Fix, each with concrete steps — just work through them in order.
1656|Start troubleshooting from "Stability & Troubleshooting → Diagnostics": abnormal items come with causes and advice, and many failures can be fixed with one click in the network rescue kit.
1657|Pages won't load / no network
1658|<b>Symptom</b>: the browser can't open any page.
1659|<b>Cause</b>: leftover system proxy settings, a bad DNS cache or an unhealthy network stack.
1660|<b>Fix</b>: open Diagnostics and check the first few results; then run "One-click rescue" in the network rescue kit (reset system proxy + flush DNS cache, no admin rights needed). If that still doesn't help, follow the on-screen prompt to reset the network stack — that requires admin rights and takes effect after a reboot.
1661|The proxy isn't taking effect
1662|<b>Symptom</b>: the internet works, but traffic doesn't go through the proxy.
1663|<b>Cause</b>: the mode was switched to Global or Direct; the system proxy is off; the core isn't running.
1664|<b>Fix</b>: open Settings → Network and check the mode is "Rule" (choosing "Global" or "Direct" changes behavior); open Settings → System → System proxy and check it's on; then confirm the core is running via the core status on the Dashboard or in Diagnostics.
1665|Some apps bypass the proxy
1666|<b>Symptom</b>: the browser works, but some programs don't use the proxy — and apps from the Microsoft Store can't open pages at all.
1667|<b>Cause</b>: this is the inherent limitation of system proxies — some programs don't read the setting; Store apps are also subject to the Windows loopback restriction, which blocks access to the local address (<code>127.0.0.1</code>) by default.
1668|<b>Fix</b>: for Store apps, open Settings → Tools → UWP app tool and flip the switch to lift the loopback restriction (needs admin rights); for other programs switch to TUN mode (see Settings → Network → TUN mode), or bind the process to a chosen line with App Routing.
1669|All nodes time out
1670|<b>Symptom</b>: every node tests as timed out.
1671|<b>Cause</b>: the nodes are temporarily unavailable, or the subscription has expired or is stale.
1672|<b>Fix</b>: first click "Test all" on the Proxies page; check whether the subscription has expired and click the "Traffic" button on its card under Profiles to refresh the info; then check the "direct exit / proxy exit" and "current node" conclusions in Diagnostics; you can also click "Update" for the subscription on the Profiles page. To clear useless timed-out nodes, turn on the "Hide timed-out" switch at the top of the Proxies page.
1673|Port already in use
1674|<b>Symptom</b>: the core can't listen; a port conflict is reported.
1675|<b>Cause</b>: the default port is taken by another program.
1676|<b>Fix</b>: the "port listening" check in Diagnostics shows which port is taken; change the mixed proxy port or the control port under Settings → Network → Ports and mode — the core restarts automatically after changes.
1677|Subscription update fails
1678|<b>Symptom</b>: clicking "Update" changes nothing.
1679|<b>Cause</b>: the subscription URL is unreachable, or the current network is down.
1680|<b>Fix</b>: confirm the subscription URL is reachable; check the error lines under Logs; if the network is down, use Diagnostics to locate the problem first.
1681|TUN won't enable / "Not elevated" warning
1682|<b>Symptom</b>: turning on "Enable TUN" has no effect, and the privilege badge shows an orange "Not elevated".
1683|<b>Cause</b>: the current process lacks admin rights, or the install directory is in use.
1684|<b>Fix</b>: go to Settings → Network → TUN mode and click "Restart as administrator", confirm the UAC prompt and retry; also make sure the install directory isn't in use.
1685|Settings changed but nothing happened
1686|<b>Symptom</b>: changing a setting doesn't change the behavior.
1687|<b>Cause</b>: core-related changes need a reload or restart of the core; or config generation failed.
1688|<b>Fix</b>: core-related changes (ports, TUN, DNS) reload or restart the core automatically; if nothing changes, check Logs for config errors and, if needed, check the Merge override or extension script under Profiles — a syntax error makes config generation fail.
1689|Data and backup
1690|<b>Symptom</b>: you need to migrate to a new machine or reinstall Windows.
1691|<b>Cause</b>: the data directory lives under the user folder on the system drive and is lost on reinstall.
1692|<b>Fix</b>: the data directory is <code>%APPDATA%\com.unboundlink.desktop</code>. Before migrating or reinstalling, open Settings → Maintenance → Backup and restore → Export backup, then restore it in the new environment with "Import backup". When you need help troubleshooting, click "Export diagnostics" first and attach the ZIP to your report.
1693|The core won't start
1694|<b>Symptom</b>: the core status never shows Running.
1695|<b>Cause</b>: the install directory is incomplete — the core sidecar is missing or damaged.
1696|<b>Fix</b>: make sure the install directory is complete (the core ships as a sidecar program with the installer); check Logs for errors; go to Settings → Maintenance → Core update and click "Check for updates" to re-fetch the core.

1700|Run Diagnostics and check the first 4 items.
1701|Use the network rescue kit.
1702|Check the mode and the system proxy.
1703|Check whether the subscription needs updating.
1704|Check for port conflicts.
1705|If the problem is hard to pin down, click Settings → Maintenance → Backup and restore → Export diagnostics and attach the ZIP to your report.

1722|Unlock Test: pick an exit node and 18 popular services are tested in one go, with "Unlocked / Partial / Blocked" badges as the verdict; each card can be retested on its own.
1723|What this page solves
1724|"I switched to a new node — can I still watch Netflix?" "ChatGPT suddenly won't sign in?" Questions like these do not need a website-by-website check. This page tests all 18 services in one pass and reports the results without delay. Requests leave through the local mixed port — the same proxy path your daily traffic takes — so what you see is the real result of the <b>current exit node</b>; switch to another route and the outcome can be completely different.
1725|How to use it
1726|<b>Pick the exit</b>: the "Exit node" row at the top has two dropdowns — pick a group, then a node; you can switch right here, and each node shows its latency;
1727|<b>Start a test</b>: click "Test all" at the top right to check all 18 in parallel, or click the refresh icon on a single card to test just that service;
1728|<b>Read the results</b>: the subtitle summarizes "Unlocked N · Partial N · Tested N/18" in real time, and each card shows a status badge and a short note.

1731|Meaning

1733|Not tested yet. Click the refresh icon on the card to run a single check.

1736|<b>Partial</b>
1737|Reachable, but with limited content — the classic case is Netflix showing only its own productions.
1738|<b>Blocked</b>
1739|Clearly unavailable; the detail line shows the HTTP status code or the region notice.
1740|<b>Failed</b>
1741|The request itself did not complete (timeout, proxy unreachable, etc.) — <b>this does not mean the service is unavailable</b>. Check the core and node status first, then test again.
1742|How the checks work
1743|Every check sends requests through the local mixed port with a browser User-Agent and a 12-second timeout. Each service is judged differently:
1744|<b>Netflix</b>: two titles are cross-checked — an original series first, and only if it returns 200, a non-original title. Both reachable means Unlocked; only the original means Partial; otherwise Blocked.
1745|<b>Disney+ / Prime Video / Spotify / TikTok</b>: the home page loads and shows no "not available in your region" notice — Unlocked.
1746|<b>Hulu / HBO Max</b>: a redirect to a region notice page, or restricted-content text on the page, means Blocked.
1747|<b>ChatGPT Web</b>: a 403 response means the region is unsupported; <b>ChatGPT iOS</b> probes a long-stable mobile status endpoint instead.
1748|<b>Bilibili</b>: an in-site API reports how Bilibili sees the exit region — mainland China gets the full catalogue, while Hong Kong, Macao, Taiwan and overseas regions are partially restricted.
1749|<b>Claude / Copilot / Gemini / X / iQIYI / Tencent Video / NetEase Cloud Music</b>: home page reachability; region limits show up as a 403 or a redirect to a notice page.
